## 4. 两种运行模式

## 4.1 文件模式

文件模式下，`--config` 传 Excel 路径。

示例：

```powershell
python run.py --config config/BC_S5.xlsx --start-date 2025-10-06 --end-date 2025-10-10
```

适用场景：

- 本地调试
- 快速 smoke test
- 排查单次输出
- 对照 Excel 输出

## 4.2 数据库模式

数据库模式下，`--config` 传配置名，不传 Excel 路径。

示例：

```powershell
python run.py --config BC_S5 --start-date 2025-10-06 --end-date 2025-10-06 --use-db
python run.py --config OC_Paste_S1_20251224 --start-date 2025-12-15 --end-date 2025-12-16 --use-db
```

适用场景：

- 配置已导入 PostgreSQL
- 需要结果落库
- 需要 `run_id` 批次隔离
- 需要 checkpoint、summary 和输出表

### 4.3 为什么 `OC_Paste_S1_20251224` 不要加引号

因为当前配置名中没有空格，下面这种写法是推荐形式：

```powershell
python run.py --config OC_Paste_S1_20251224 --start-date 2025-12-15 --end-date 2025-12-16 --use-db
```

只有参数值中包含空格时才需要引号。

## 6. 输出去哪里看

### 6.1 文件模式输出

输出路径通常位于：

```text
outputs/<config_stem>/run_YYYYMMDD_HHMMSS/
```

常见子目录：

- `module1/`
- `module3/`
- `module4/`
- `module5/`
- `module6/`
- `orchestrator/`
- `summary/`

### 6.2 数据库模式输出

数据库模式下，业务结果进入 PostgreSQL；本地主要保留日志目录。

日志路径通常位于：

```text
outputs/db_<config_name>_<timestamp>/
```

其中会包含：

- `simulation_log_*.txt`

### 6.3 如何确认数据库模式是否真的成功

至少看四件事：

1. 终端日志里最后状态是否为 `completed`
2. `sim_checkpoint` 中对应 `run_id` 是否为 `completed`
3. 核心输出表是否有数据
4. `orch_state_json` 是否仍保持轻量，不再写入历史大对象

## 7. 数据库模式的配置来源

### 7.1 默认数据库配置

项目当前默认数据库配置在：

- `config/database.json`

默认值为：

- host：`localhost`
- port：`5432`
- database：`test_db`
- user：`postgres`

### 7.2 `OC_Paste_S1_20251224` 的配置文件

当前仓库根 `config/` 下已经存在：

- `config/OC_Paste_S1_20251224.xlsx`

这是为了保证数据库模式在“只按 `config/`、`test_files/`、仓库根”搜索配置时能稳定识别到该配置。

## 8. 当前最重要的运行特性

### 8.1 checkpoint 已做轻量化

当前分支已经修复 PostgreSQL `jsonb` 过大问题，checkpoint 不再写入大历史对象：

- `delivery_gr`
- `shipment_log`
- `daily_logs`
- `m1_previous_orders`

### 8.2 M4 集成适配层已规范化命名

当前应使用：

- `src/core/main_integration/production_integration.py`

而不是已删除的：

- `src/core/main_integration/module4_runner.py`

### 8.3 模块兼容壳已删除

当前不应再写这种导入：

```python
from src.modules import module1, module4, module6
```

应改为：

```python
from src.modules import demand_planning as module1
from src.modules import production_planning as module4
from src.modules import logistics_execution as module6
```

## 9. 常见问题

### 9.1 为什么 VSCode 里旧文件不见了，但 Git 里显示很多删除

因为第三阶段已经物理删除这些 legacy 文件。  
这是预期行为，说明文件树已经收口到真正的包结构。

### 9.2 为什么数据库模式有时会因为 `Temp` 目录失败

在受限环境或沙箱环境里，临时目录写入可能被拦截。  
如果命令本身没有逻辑错误，但报 `AppData\Local\Temp` 访问失败，需要在可写环境里重跑。

### 9.3 为什么数据库模式需要的是配置名，不是 Excel 路径

因为数据库模式会按 `config_name` 去查 `cfg_*` 表，并以同名配置组织运行结果。

### 9.4 现在最可信的架构说明是哪一份

优先看：

- `docs/OPTIMIZED_CODE_STRUCTURE_DIAGRAM.md`
- `docs/交接文档/Refactored/项目交接文档.md`

## 10. 建议的接手方式

1. 先跑一次 `BC_S5` 文件模式短窗验证环境。
2. 再跑一次 `BC_S5` 数据库模式确认 DB 链路。
3. 最后跑 `OC_Paste_S1_20251224` 两天数据库回归确认当前分支结构收口没有漂移。
4. 修改结构性代码后，默认复跑第 3 步。
