# 性能优化测试职责说明

**版本**: 1.0.0  
**适用范围**: ChainSight 性能优化与基准测试

## 🎯 目标
- 量化优化收益（耗时、资源、吞吐）。
- 发现性能回退并可复现。
- 输出可审计、可比较的测试证据与报告。

## 👥 角色与职责

### 1) 性能测试负责人（Owner）
- 制定测试计划、基准场景与指标口径。
- 维护基准数据集与配置（如 BC_S5、SIT 配置）。
- 评审与确认性能回退阈值。
- 汇总并发布报告。

### 2) 研发负责人（Dev Lead）
- 对优化点给出可验证的预期收益与范围说明。
- 提供可重复执行的运行参数与环境要求。
- 修复性能回退并提交原因分析。

### 3) 执行测试工程师（Tester）
- 在固定环境运行基准测试与对比测试。
- 记录关键参数、日志、输出路径与版本信息。
- 产出对比报告与异常说明。

### 4) 数据与配置维护者（Data/Config）
- 维护 Excel/数据库配置一致性与版本标记。
- 记录配置变更对性能的潜在影响。

## ✅ 测试范围
- **核心链路**: M1→M4→M5→M6→M3 日循环。
- **运行模式**: 本地文件模式 & 数据库模式（含 DuckDB/Optimized 分支）。
- **关键模块**: M1、M3、M4、M5、M6、Orchestrator。
- **性能关键点**: I/O、数据加载、数据管道、并行执行、写库。

## 📏 指标与口径
| 指标 | 口径 | 采集位置 |
|------|------|----------|
| 总耗时 | 从启动到结束 | run.py 输出日志 / performance 报告 |
| 单日耗时 | 每个仿真日周期 | orchestrator/performance | 
| 模块耗时 | 每模块执行时间 | module*/performance 或日志 |
| 峰值内存 | 进程峰值 | OS 监控/脚本采集 |
| I/O 时延 | 读写耗时 | 数据管道日志 |

## 🧪 基准测试清单

### A. 基准回归（必测）
- 配置：test_files/BC_S5.xlsx
- 命令（本地文件模式）：
  - python run.py --config test_files/BC_S5.xlsx --start-date 2025-10-06 --end-date 2025-10-10
- 输出：outputs/BC_S5/run_*/performance/

### B. 数据库模式（必测）
- 配置：BC_S5
- 命令：
  - python run.py --config BC_S5 --start-date 2025-10-06 --end-date 2025-10-10 --use-db
- 输出：outputs/db_BC_S5_*/

### C. 优化模式对比（选测）
- run_with_duckdb.py / run_optimized.py / optimized_processor.py
- 仅在涉及相关优化点时执行。

## 🧾 产出物要求
- **测试报告**: 运行参数、环境、指标对比、结论。
- **日志与输出**: 输出目录结构完整、可追溯。
- **差异说明**: 若有回退，必须包含原因分析与复现说明。

## ⚠️ 质量门禁（示例）
- 总耗时回退 > 10% 需阻断合并。
- 峰值内存回退 > 15% 需说明原因与修复计划。
- 关键模块耗时回退 > 10% 需定位模块级原因。

## 🧰 建议工具
- Windows 性能监视器 / Resource Monitor
- Python 性能分析器（项目内 performance_profiler.py）
- 运行日志与 outputs/performance 目录
